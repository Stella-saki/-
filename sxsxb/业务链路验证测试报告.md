## 一、测试目标与范围

验证“首轮选报 → 面试考核 → 拟录取确认 → 二轮补录（二面）→ 三轮补录 → 统筹调剂（内部/跨室/约谈）→ 调剂后确认”的完整业务链路，重点覆盖：

1. 意向填报、提交与不可撤回规则；
2. 面试场次排期、自动排人、面试提醒派发与回执；
3. 签到、多评委评分、总分聚合；
4. 拟录取、拟录取通知与名额占用；
5. 补录轮次的资格限制与单意向限制；
6. 调剂三级策略（内部调剂、跨实训室调剂、约谈统筹）；
7. 调剂后学生确认与名额释放；
8. 关键业务留痕与数据一致性。

### 9.5 导师容量规则调整（2026-11-09）

按最新规则，意向填报阶段**不再限制单个导师的选报人数**，导师“可带人数”只约束最终录取人数：

| 环节 | 调整前 | 调整后 |
|---|---|---|
| 学生填报意向 | 展示导师容量，可能被误读为选报上限 | 不限制选报人数，界面容量文案改为“可带 X 人” |
| 拟录取（`/api/results/propose`） | 仅校验实训室名额 | 增加导师余额校验，达上限返回 409 |
| 调剂 / 约谈落库 | 可能选中已满导师 | `pick_mentor` 只返回仍有余额的导师，落库前再次校验 |
| 内部调剂 | 无可用导师时回退到原导师 | 不再回退，转入跨室调剂或第三级约谈 |

验证脚本 `tests/verify_mentor_capacity.py`：**17 项全部通过**，覆盖“5 名学生选报同一导师（容量 3）全部成功”与“导师录取达 3 人后再录取被 409 拒绝”；`tests/e2e_verify.py` 回归 **30/30 通过**。

### 9.6 解除硬性时间限制（2026-11-12）

为便于演示与线下流程灵活推进，阶段时间窗改为**软约束**，以轮次/阶段状态为唯一开关：

| 环节 | 调整前 | 调整后 |
|---|---|---|
| 当前轮次判定 | 仅取 `NOW()` 落在 `fill_start~fill_end` 的轮次 | 优先取手动开启的 `FILLING` 轮次，时间窗仅兜底 |
| 建立申请 / 保存意向 | 校验时间窗，窗口外返回 409 | 仅校验轮次状态 `FILLING` |
| 创建面试场次 | 须落在轮次面试窗口内且开始时间晚于当前 | 仅校验起止时间先后与评委合法性 |
| 评委提交评分 | 场次开始前禁止评分 | 不再校验场次时间 |
| 学生确认录取 | 超过 12 小时确认期限即拒绝 | 不再拦截，截止时间仅作提醒 |
